래스터 스캔 방식: 픽셀 단위로 스캔 라인을 따라 한 줄씩 출력, 프레임 버퍼에 저장 후 주기적으로 재생. 이중 프레임 버퍼 사용. 메모리를 많이 쓰고 선에 계단 현상이 생길 수 있음.

점과 선

  • 점: 래스터 장치에서는 픽셀, 기하 공간에서는 좌표 (x, y). 속성은 크기, 명암, 색, 모양.
  • 선: 양 끝점으로 정의. 절대좌표(시작점, 끝점) 또는 상대좌표(시작점, 증가값 Δx Δy).
  • 직선 y = mx + c, m = (y2 − y1)/(x2 − x1), c = y1 − m·x1.

DDA 알고리즘 출제

x 또는 y를 1씩 늘리면서 다른 좌표에 기울기만큼 더하고, 그 값을 반올림해 픽셀을 정한다

기울기한 칸씩 늘리는 쪽다음 픽셀
|m| ≤ 1x(xk + 1, round(yk + m))
|m| > 1y(round(xk + 1/m), yk + 1)
  • 초기화: Δx = xb − xa, Δy = yb − ya, m = Δy/Δx, 시작점 (xa, ya).
  • 특징: 곱셈 없이 실수 덧셈만 반복. 하지만 부동소수 연산이라 정수 연산보다 느리고, 반올림 시간이 걸리며, 오차가 누적될 수 있다.

브레즌햄 선 그리기 출제

0 ≤ m ≤ 1일 때 다음 점은 (x+1, y) 또는 (x+1, y+1) 둘 중 하나. 판단 매개변수 p의 부호로 고른다. 정수 덧셈만 써서 빠르다

  • d1 = 실제 y − yk, d2 = (yk + 1) − 실제 y. pk = Δx(d1 − d2).
  • 초기값: p1 = 2Δy − Δx, C1 = 2Δy, C2 = 2(Δy − Δx)
  • p < 0 → d1 < d2 → 다음 점 (x+1, y), p += C1

접기 횟수 규칙은 방향을 보니까, 안쪽 사각형을 어느 방향으로 그렸느냐에 따라 구멍이 생기기도 하고 안 생기기도 해요. 홀짝 규칙은 방향과 상관없이 2번 만나니까 항상 구멍이에요.

시험에서 푸는 순서

  1. 판단할 점에서 한쪽(보통 오른쪽)으로 수평선을 긋는다.
  2. 홀짝 규칙: 테두리와 만나는 점을 센다. 홀수면 내부, 짝수면 외부.
  3. 접기 횟수 규칙: 만나는 변마다 방향을 본다. 아래로 가는 변 +1, 위로 가는 변 −1. 다 더해서 0이 아니면 내부, 0이면 외부.

+1 −1 부호는 반대로 잡아도 돼요. 같은 방향끼리는 더해지고 반대 방향끼리는 지워진다는 것만 맞으면 판단 결과는 같아요.

영역 채우기 다각형 알고리즘

  • 영역 = 같은 색의 이웃 픽셀 집합. 4방향 연결, 8방향 연결. 경계가 8방향이면 내부는 4방향, 경계가 4방향이면 내부는 8방향으로 채운다.
  • 시드 채우기: 내부 한 점(시드)에서 이웃으로 퍼짐, 재귀 사용, 페인팅 프로그램.
    • Flood Fill: 기존 영역 색과 같은 색이면 채우고 계속
    • Boundary Fill: 경계색을 만나면 멈춤, 경계색도 채우기 색도 아니면 채움
  • 다각형 주사 변환(주사선 채우기): 주사선마다 다각형 내부 구간을 구해 칠함, 벡터 그리기 소프트웨어.
  • y-x 주사선 알고리즘: 에지를 작은 y 순서로 정렬한 EL(Edge List), 현재 주사선과 만나는 에지만 모은 AEL(Active Edge List). 매 주사선마다 끝난 에지(yb < yk)는 AEL에서 빼고, 시작하는 에지(ya = yk)는 EL에서 AEL로 옮긴 뒤, 교차점 x를 정렬해 두 개씩 짝지어 그 사이를 칠한다. 일관성(coherence) 덕분에 효율적.

  • C 기반. 포인터 없음(동적 할당 없음), 함수 오버로딩 가능, 재귀 불가, 구조체 가능, 인자는 모두 call-by-value.

셰이더 프로그램 만들기 10단계 ★

셰이더 객체 만들기(생성 → 소스 → 컴파일) × 2 → 프로그램(생성 → 붙이기 → 링크) → 활성화

vertexShader = glCreateShader(GL_VERTEX_SHADER);          // 1 생성
glShaderSource(vertexShader, 1, &source, NULL);           // 2 소스 지정
glCompileShader(vertexShader);                            // 3 컴파일
fragmentShader = glCreateShader(GL_FRAGMENT_SHADER);      // 4
glShaderSource(fragmentShader, 1, &source, NULL);         // 5
glCompileShader(fragmentShader);                          // 6
GLuint shaderID = glCreateProgram();                      // 7 프로그램 생성
glAttachShader(shaderID, vertexShader);                   // 8 붙이기
glAttachShader(shaderID, fragmentShader);
glLinkProgram(shaderID);                                  // 9 링크
glDeleteShader(vertexShader);                             // 링크 후엔 필요 없음
glDeleteShader(fragmentShader);
glUseProgram(shaderID);                                   // 10 사용
  • 셰이더 = 하나의 단계 코드, 셰이더 프로그램 = 여러 셰이더를 링크한 실행 프로그램.
  • 에러 확인: glGetShaderiv(shader, GL_COMPILE_STATUS, &result) → 실패면 glGetShaderInfoLog. 프로그램은 glGetProgramiv(id, GL_LINK_STATUS, ...) → glGetProgramInfoLog.
  • 셰이더 코드는 C++에서 문자열로 읽어(filetobuf) 실행 시점에 GPU로 보내 컴파일.

VBO와 VAO

VBO = 데이터 저장, VAO = 데이터 연결 방법 저장. VAO에는 정점 데이터가 직접 들어가지 않는다

  • VBO: 정점 데이터를 GPU 메모리에 저장하는 버퍼. 하나에 여러 속성 가능.
  • VAO: 어떤 VBO의 어떤 형식 데이터를 어느 location이 가져갈지. 보통 Mesh 하나에 VAO 하나.
  • 바인드: 앞으로 작업할 객체를 현재 대상으로 지정.
glGenVertexArrays(1, &VAO);
glBindVertexArray(VAO);

glEnableVertexAttribArray(0);
// 그릴 때

정점의 인덱스(사용 순서)를 저장해 중복 정점을 줄이고 재사용. VBO = 정점 데이터, EBO = 사용 순서

     0.5f, -0.5f, 0.0f,   // 1 우측 하단
    -0.5f, -0.5f, 0.0f,   // 2 좌측 하단
    -0.5f,  0.5f, 0.0f }; // 3 좌측 상단

                         1, 2, 3 };  // 두 번째 삼각형
glGenBuffers(1, &EBO);

동차좌표 ★

(x, y, z) → (x, y, z, w). w = 1이면 점, w = 0이면 벡터. 이동·회전·신축을 모두 행렬 곱 하나로 통일

  • 벡터 공간: 크기와 방향만, 위치 무관. 어파인 공간: 점(위치)과 벡터를 구분.
  • 이동 행렬을 점에 곱하면 이동, 벡터에 곱하면 그대로(w = 0이라 tx가 안 더해짐).
  • w ≠ 0이면 실제 좌표 = (x/w, y/w, z/w). (1, 2, 4, 1), (2, 4, 8, 2), (5, 10, 20, 5)는 모두 (1, 2, 4).
T = | 1 0 0 tx |    T·(x, y, z, 1) = (x+tx, y+ty, z+tz, 1)   점 이동
    | 0 1 0 ty |    T·(x, y, z, 0) = (x, y, z, 0)            벡터는 안 바뀜
    | 0 0 1 tz |
    | 0 0 0 1  |

클리핑과 점 클리핑

Liang-Barsky 선 클리핑 ★ 출제 클리핑

매개변수 방정식 P(u) = P1 + (P2 − P1)u, 0 ≤ u ≤ 1. u의 유효 구간 [ustart, uend]를 구한다

  • x = x1 + dx·u, y = y1 + dy·u (dx = x2 − x1, dy = y2 − y1). u = 0이면 P1, u = 1이면 P2.
  • 조건 u·pk ≤ qk, k = 1~4:

  • pk < 0: 밖 → 안으로 들어감. ustart = max(0, qk/pk)
  • pk > 0: 안 → 밖으로 나감. uend = min(1, qk/pk)

산란반사 공식 ★

주변 조명 I = Ka·Ia (0 < Ka < 1)

  • Ia: 주변 조명 밝기, Ka: 주변 조명 반사 계수(물질마다 다름).
  • 램버트 코사인 법칙: 표면이 받는 빛의 양은 cosθ에 비례. cosθ = N·L (N 법선, L 표면에서 광원 방향, 둘 다 단위벡터).
  • 정면으로 향하면 가장 밝고, 비스듬하면 어두움.

점광원 산란 I = (Ip / d)·Kd·(N·L)
Lambert 조명 모델 I = Ka·Ia + (Ip / d)·Kd·(N·L)

구현할 땐 뒷면에서 N·L < 0이 될 수 있어서 max(0, N·L).

예) N = (0, 1, 0), L = (0.6, 0.8, 0), Ip / d = 1, Kd = 0.5, Ka·Ia = 0.1
N·L = 0·0.6 + 1·0.8 + 0·0 = 0.8 (θ ≈ 36.9°)
I = 0.1 + 1·0.5·0.8 = 0.5
L이 (0, 1, 0)으로 정면이면 N·L = 1 → I = 0.6, 옆 (1, 0, 0)이면 N·L = 0 → I = 0.1 (주변광만)

숫자 예제는 공식 확인용으로 만든 값이에요.

거울반사와 Phong 조명 모델 ★

  • L 빛의 입사 방향, N 법선, R 반사된 빛의 방향, V 표면에서 관찰자 방향, Φ는 V와 R 사이 각.
  • Φ가 0°에 가까울수록(관찰자가 반사 방향에 가까울수록) 강하다.
  • 반짝이는 표면일수록 반사 범위가 좁다.

Phong 거울반사 I = (Ip / d)·Ks·cosⁿΦ = (Ip / d)·Ks·(V·R)ⁿ

  • Ks: 거울반사 계수. 반짝일수록 크다.
  • n: 광택 정도. 광택 많으면 n이 크고, 없으면 작다. cosΦ가 0~1이라 n이 크면 값이 급격히 작아져 하이라이트가 좁아짐.
  • 구현할 땐 max(0, V·R)ⁿ.
예) V·R = 0.8일 때 n = 8 → 0.8⁸ ≈ 0.168, n = 256 → 거의 0. 광택이 크면 조금만 벗어나도 하이라이트가 사라짐

Phong 조명 모델 I = Ka·Ia + (Ip / d)·[Kd(N·L) + Ks(V·R)ⁿ]

  • 광원이 멀면 N·L이 표면 위치와 상관없이 일정. 관측자가 멀면 V·R이 일정.
